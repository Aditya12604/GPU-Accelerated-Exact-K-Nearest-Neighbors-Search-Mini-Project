# Exact Top-k Cosine Similarity Search

Implementations of exact top-k cosine similarity search for a high-performance computing comparison:

- Serial C++ baseline
- OpenMP multi-core CPU implementation
- CUDA GPU implementation for Google Colab

All implementations use the same deterministic random input generation, row normalisation, cosine-similarity computation, deterministic tie-breaking, and machine-readable CSV output where applicable.

## Problem

Given a database of `N` vectors with dimension `d` and `Q` query vectors, find the `k` database vectors with the highest cosine similarity for every query.

Each vector is normalised to unit length first, so cosine similarity becomes a dot product:

```text
cosine(q, x) = dot(normalize(q), normalize(x))
```

The result is exact: the implementations scan all database vectors and select the best `k` scores. Ties are resolved by choosing the smaller database index.

## Repository Contents

| File | Description |
| --- | --- |
| `serial_topk.cpp` | Single-threaded C++17 reference implementation using a size-`k` min-heap. |
| `openmp_topk.cpp` | OpenMP implementation with hierarchical and per-query top-k strategies. |
| `cuda_topk_colab.ipynb` | CUDA implementation and benchmark notebook for Google Colab. |

## Requirements

### CPU implementations

- C++17 compiler
- OpenMP support for the OpenMP version

On macOS, install GCC with Homebrew if the system compiler does not provide OpenMP:

```bash
brew install gcc
```

### CUDA implementation

- Google Colab with a CUDA-enabled runtime
- NVIDIA GPU, such as a T4
- `nvcc`

Open `cuda_topk_colab.ipynb` in Colab, select **Runtime -> Change runtime type -> T4 GPU**, and run the notebook cells in order.

## Build

### Serial

```bash
g++ -O3 -march=native -std=c++17 serial_topk.cpp -o serial_topk
```

### OpenMP

```bash
g++ -O3 -march=native -fopenmp -std=c++17 openmp_topk.cpp -o openmp_topk
```

On macOS with Homebrew GCC, use the installed versioned compiler if `g++` does not support OpenMP, for example:

```bash
g++-15 -O3 -march=native -fopenmp -std=c++17 openmp_topk.cpp -o openmp_topk
```

### CUDA

The CUDA source is generated by the notebook's `%%writefile cuda_topk.cu` cell and compiled in Colab:

```bash
nvcc -O3 -arch=sm_75 cuda_topk.cu -o cuda_topk
```

Use the architecture matching the GPU. For example, T4 uses `sm_75`, A100 uses `sm_80`, and L4 uses `sm_89`.

## Usage

The CPU programs accept:

```text
program N d Q k [batch] [mode]
```

Where:

- `N`: number of database vectors
- `d`: vector dimension
- `Q`: number of query vectors
- `k`: number of nearest neighbours to return
- `batch`: number of queries processed at a time
- `mode`: OpenMP mode, either `hier` or `query`

### Serial example

```bash
./serial_topk 200000 384 64 10 32
```

### OpenMP examples

```bash
OMP_NUM_THREADS=8 ./openmp_topk 200000 384 64 10 32 hier
OMP_NUM_THREADS=8 ./openmp_topk 200000 384 64 10 32 query
```

The `hier` mode selects local top-k candidates per thread and merges them. The `query` mode assigns complete queries to threads.

### CUDA examples

Run these commands in the CUDA notebook after compiling:

```bash
./cuda_topk 200000 384 64 10 32
./cuda_topk 1000000 768 256 10 64
```

The CUDA program uses the same arguments: `N d Q k [batch]`.

## Implementation Overview

1. Generate database and query vectors with fixed seeds (`42` for the database and `7` for queries).
2. Normalise every vector to unit length.
3. Compute all query-to-database dot products in batches.
4. Select the exact top-k results using deterministic ordering.
5. Report normalisation, similarity, top-k, total time, throughput, and checksum.

The CUDA implementation additionally uses tiled shared-memory matrix multiplication and hierarchical top-k reduction across threads, warps, and blocks. It verifies the first few queries against a double-precision CPU reference and reports `recall@k` and maximum score error.

## Benchmarking

For comparable results, use the same `N`, `d`, `Q`, `k`, and batch size across implementations. Run each configuration several times after a warm-up and record the `CSV,...` output line.

The CUDA notebook includes sweeps over:

- Database size `N`
- Vector dimension `d`
- Number of neighbours `k`

Example large configuration:

```text
N = 1,000,000
d = 768
Q = 256
k = 10
batch = 64
```

GPU memory usage depends heavily on `N`, `d`, and `batch`, because the CUDA implementation stores a batch of similarity scores. Reduce `N` or `batch` if the GPU does not have enough memory.

## Output and Correctness

Each run prints the timing breakdown, throughput, checksum, and the first few results for query 0. The checksum is useful for comparing implementations using identical inputs.

The OpenMP and CUDA versions include correctness checks against CPU references. Floating-point reduction order can cause small score differences, but the selected top-k indices should match for normal non-tied inputs.
